# Minerva export with onshape-to-robot

This directory is the detailed visual source and 1.1 comparison baseline. The
active Minerva model now combines these visuals with
[simplified 1.2 collision geometry](../collision-v1.2/README.md). Use this
directory's [model.json](model.json) to inspect or benchmark the old complete
1.1 collision model explicitly.

The export uses `onshape-to-robot==1.8.2`, pinned to
the immutable **3DP URDF Version 1.1** assembly in [config.json](config.json).
Retrieved once and converted offline on 2026-09-19. The [URDF](minerva.urdf)
passes the [structural audit](audit.json): **17 links, 12 arm revolutes,
four jaw slides and two mimic relations**. Both arms follow j1 through j6.
The [manifest](source_manifest.json) records source properties and asset hashes.

Version 1.1 corrects the left shoulder: the first joint mount moved 7.5 mm
vertically and the second joint's lateral offset was corrected. This update
used one version lookup and one retrieval (519 network requests recorded by
the exporter wrapper); conversion, audits and collision sweeps run offline.
The local 1.0 snapshot is retained under ignored `simulation_runs/` for comparison.

This corrects the native export's joint graph. No CAD regrouping is indicated
by that earlier export. Physical dynamics are still unvalidated:

- All 129 source parts have zero mass/inertia. Exported `1e-9` values are
  numerical floors, not physical measurements.
- All 12 arm limits are absent in CAD. Exported `[-pi, pi]` ranges and effort/
  velocity values of `10` are tool defaults, not operating permissions.
- Four jaw strokes are source-defined at 48.2 mm. Each B jaw mimics A with
  multiplier `+1`; their opposite spatial axes give opposed jaw movement.
  Motor radians still need calibration to jaw metres.
- Mesh collision elements are present but need contact-pair review, clearances
  and runtime performance validation before use as an operating gate.

Arm limits will be measured independently, with separate whole-robot collision
checking during operation; see the [collision and calibration plan](../../../docs/architecture/COLLISION_AND_LIMIT_CALIBRATION.md).

The [native Onshape export](../README.md) is retained separately for comparison.
Its extra planar/cylindrical coordinates do not prove that this tool will
produce the same graph. In 1.8.2, named Cylindrical/Revolute mates export as
revolute joints, `dof_` is stripped, rigid groups are merged, and unrelated
positioning mates are not turned into independent robot joints.
[Design conventions](https://onshape-to-robot.readthedocs.io/en/latest/design.html).

## Local credentials

Fill the ignored `.env` file in **this directory**, using an Onshape key with
read access to the selected document:

```dotenv
ONSHAPE_API=https://cad.onshape.com
ONSHAPE_ACCESS_KEY=
ONSHAPE_SECRET_KEY=
```

Keep the values in that local file. The `.env` pattern is ignored by Git; keys
do not belong in the tracked config. Run from this directory so the exporter's
dotenv lookup finds this file. Authentication uses environment variables; an
already-set process variable takes precedence over `.env` in this version.
[Authentication instructions](https://onshape-to-robot.readthedocs.io/en/latest/getting_started.html#setting-up-your-authentication).

## Retrieve once, then convert locally

Use the project Python environment. The optional `cad` dependency group pins
the exporter; it is already installed on the current development machine.

From this directory:

```sh
python -m onshape_to_robot.export . --retrieve --safe
python -m onshape_to_robot.export . --convert --safe
```

For the existing Windows environment, substitute
`../../../.venv-platform/Scripts/python.exe` for `python`.

- `--retrieve` downloads this versioned assembly and its required part data,
  writes mesh assets and saves a local `robot.pkl` snapshot. One retrieval run
  can make many API calls; an exact count or account quota has not been assumed.
- The explicit element/version IDs avoid assembly/workspace discovery. Retain
  the exporter's cache at `~/.cache/onshape-to-robot/` for cacheable responses.
  Do not clear it or repeatedly retrieve to adjust output formatting.
- After successful retrieval, `--convert` reads the local snapshot and writes
  `minerva.urdf` without constructing an API client. Check the actual snapshot
  and URDF artifacts: this exporter can exit with status 0 on an API error.
  On Windows, normalize its `package://meshes\\file.stl` references to portable
  `meshes/file.stl` paths afterward. This local normalization was applied to
  all 258 visual/collision references; its original output hash is recorded.
- `--safe` disables custom commands/imports. It does **not** make arbitrary
  pickle files safe. Use only `robot.pkl` generated by this local retrieval.
  The pickle is ignored by Git.
- Stop on authentication or quota errors and inspect the cause rather than
  automatically retrying. Record source hashes and exporter version with the
  resulting assets before using them in simulation.

The default configuration preserves source limits and requests source dynamics.
Materials/mass overrides were not assigned in this frozen version, so exported
mass properties remain unvalidated. This first comparison can establish the
joint graph even before a later version has measured physical properties.

## Audit the result

From the repository root after conversion:

```sh
python -m robot_platform sim audit-model --urdf urdf/minerva/onshape-to-robot/minerva.urdf --package-root urdf/minerva/onshape-to-robot --expectations urdf/minerva/onshape-to-robot/expected_joints.json
```

The expected names omit `dof_`, matching this exporter. Audit the 12 arm
rotations, four mechanical jaw slides, jaw coupling, source limits, geometry
scale and mass properties before integration. The two gripper control inputs
remain motor radians; finger slides remain metres. Mesh-derived collisions
and default effort/velocity values are not validated contact or actuator data.

Do not change the CAD mate structure solely to match the native exporter.
Only propose source changes after inspecting this tool's output and warnings.
